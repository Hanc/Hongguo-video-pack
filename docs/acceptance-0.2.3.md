# 0.2.3 搜索封面修复验收

日期：2026-10-19（Asia/Shanghai）。这是封面修复版，不扩大 0.2.2 的访客初始化或账号能力。

## 修复与依据

- App 搜索的签名封面 URL 实测返回 `image/heic`，原始字节为 HEIC；直接改 URL 后缀为 JPEG/WebP 返回 403。
- 按同一剧集 ID 查询官网 `/detail`，核对 `seriesDetail.series_id` 后，取得该剧集自己的 JPEG 封面。
- 搜索结果先展示，详情补充在后台最多 3 个并发、逐张通知；不等待封面才结束首批加载，不扫描分类片库。
- 复用已校验的详情数据；缓存不会把其他查询的旧标题/热度覆盖到新结果，补图不替换已有热度。
- 详情失败或 ID 不匹配时保留原结果，可刷新重试；翻页或换关键词后，旧响应不能覆盖当前页，也不继续启动旧批次的排队请求。

## 验证

- Flutter 自动化测试：36 项通过、4 项跳过。新增覆盖非阻塞补图、缓存保留当前数据、错误 ID/失败重试、逐张更新与并发/过期工作控制。
- 真实来源两页搜索：5 条与 9 条，ID 无重合，返回上页缓存有效。
- 同一批 14 条结果均完成详情补图，下载实际封面字节后，14 张均通过 Flutter 图片解码，不只是核对 HTTP 200 或图片后缀。
- Windows 成品提供 `--search-acceptance`：用本机访客配置验证两页搜索、缓存，并实际下载与解码全部封面，报告写入 `.local/search-acceptance/result.json`，不输出身份和签名值。
- 原始记录与图片样本只在 `.local/traffic-infra/`，不进入交付包。

## 用户验收

1. 结束旧版任务并退出旧版，安装 0.2.3。
2. 搜索“重生”：剧集结果先出现，封面随后逐张补齐；热度和剧集数应保留。
3. 翻到下一页，再返回上一页：内容不应重复，已补齐的封面应复用。
4. 补图过程中换关键词或翻页：旧图片和旧结果不能覆盖当前查询。

本机访客配置仍保存在用户自己的应用数据目录，升级不将它打入安装包。新设备自动访客注册尚未完成；无本机配置时仍是明确标注的网页首批。Android 构建与 Flutter 共享代码测试不能替代真实手机的完整验收。
