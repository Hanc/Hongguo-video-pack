# 播放倍速与连播预取

## 用户原始需求（逐字保留）

```text
首先是倍速功能，其次是每次自动连播下一集的时候会有个网络卡顿的黑屏，理应提前缓存，直接无感过渡
```

```text
缓存续播有个问题，如果切换到全屏的话，画面会暂停，其次如果在暂停状态下声音也能继续不知道为什么，这个缓存续播的改动很大吗，找一个能复用的方式就行，不用自己改，去搜一下成熟的方案来
```

## 必须满足的行为

- 播放页提供 0.5x / 0.75x / 1x / 1.25x / 1.5x / 1.75x / 2x 倍速，作用于当前播放。
- 倍速入口属于播放器能力，放在播放器控制栏内，不占用播放页正文布局。
- 倍速在切集、切画质后继续生效；退出播放页再进入沿用上次选择。
- 倍速只改变播放速率，不改变取流画质，不影响拼接导出。
- 自动连播时提前取好下一集的取流结果，切集不再重新签名与请求。
- 预加载不改变来源规则：仍使用同一条签名取流链路与实际返回画质，不虚构清晰度、不伪造登录。
- **暂停必须是彻底的**：暂停后播放位置不得继续前进，也不得有声音继续。
- **切全屏不得中断播放**。

## 方案与边界

- 播放器使用单个 `Player`（media_kit 标准用法）。**不得**再用第二个 `Player` 做"预开下一集"：双实例会导致全屏切换画面暂停、暂停后另一通道仍在出声，与官方控件行为不一致。
- 官方 playlist 方案在本项目不可用：`Media` 只接受 `uri` / `httpHeaders` / `extras`，没有 per-file 的 mpv/lavf 选项，而每集使用独立的 CENC 解密键，playlist 无法为每条目设置 `decryption_key`。
- 连播加速只在控制器层做：提前调用取流接口拿到下一集地址并缓存在内存中。
- 缓存的取流结果必须短期有效（默认 2 分钟），因为签名地址会过期；命中缓存后开流失败要重新取流并重试一次，不能把过期地址当成可用资源。
- 只预取"下一集"，不预取整季；关闭自动连播即不再预取。
- 未命中预取时回退为按需取流，此时会有一次网络等待；不得宣称任何条件下都无等待。

## 验收

- `--switch-acceptance` 必须断言 `pausedPositionFrozen`（暂停后位置零位移）与 `rateRetained`（切集后倍速保持）。
- `--playback-acceptance` 必须覆盖真实来源两集出帧与拖动。
- Windows 的 `ProductName` 版本资源必须使用 Unicode 字符串块并以 UTF-8 BOM 保存源文件。
- 签名 worker 必须能在应用支持目录或临时目录落盘，全部不可写才允许报错。
