# 观看记录与续播

## 用户原始需求

> 继续开发，现在需要支持观看记录，包括哪个剧 哪一集 哪个点，点击可以继续从那个点观看，合成视频也要包含在历史记录中，除非视频被删除。存本地data中，可以在历史中删除，也有自动失效规则：首先完整看完的（最后一集观看超过80%）标记为已看过，比如超过50个之后优先删除已看过的，然后是比较上一次观看最早的那个进行自动删除，同一个系列剧（除了第n剧的n不同其他一样的）只会记录一个历史数据。
> 刚打开程序或者app 优先看到的一行最近的3个历史记录的卡片。
> 难点可能是观看合成的视频并且继续之前的点位播放，我感觉必须增加本地文件播放器并且强制用他来播放我们自己合成的视频才能解决问题。 你看看这些功能有没有阻塞点 没有的话开工

## 实施口径

- 应用本地支持目录 `data/watch-history.json`，串行原子写入及 `.bak` 备份；不写安装目录，不保存取流签名、密钥、账号或播放 URL。
- 默认首页顶部一行最近三条；完整历史支持继续、查看同系列文件、手动删除。删除历史不删文件，旧导出索引重启迁入不得复活手动删除的记录；主动播放可重新登记。
- 保存具体剧 ID、分集 ID/集号、毫秒位置、时长及更新时间。只在最后一集位置严格超过时长 80% 标为已看过；无时长不判定。合成文件按单文件 80% 判断。
- 只归并明确“第 N 季/部/卷/篇/剧”的序号差异，其余标题文字必须相同，不删副标题或模糊合并。一个系列保存最近在线点位和各合成文件各自点位。
- 在线记录上限默认 50：优先删已看过的，同优先级按最后观看最早淘汰。有合成文件的系列另行保留，不计入 50 条名额，避免文件多时无法保存在线记录。合成文件不存在时清除其记录，系列还有其他来源则保留。
- 合成成功即登记，失败/取消不登记。去掉导出索引 20 条截断，迁入旧的有效导出记录。
- 所有应用内“打开导出视频”统一走内置播放器。文件 URI 不附网络头、清除旧解密参数；打开新播放器先暂停旧播放器。
- 播放中每 5 秒保存，暂停、切集前、离开播放页、后台和关闭窗口额外提交。暂停不刷新最近观看时间，加载中不把旧点位写进新集。启动、前台、打开/下拉历史时检查文件存在性。
- 此规格在用户验收前保持 active。单元/界面测试、真实 Windows 播放和 Android 构建/手机验收分别记录，不互相替代。
