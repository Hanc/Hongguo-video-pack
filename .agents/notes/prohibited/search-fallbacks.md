# 禁止默认全片库扫描与伪分页

## 已证实的问题

早期搜索先扫描多个分类的全部页面，再本地匹配，且等待热度补充后才展示结果。用户明确反馈搜索慢，并质疑是否一次取回全量数据。该实现还受分类片库覆盖范围限制，不能视作全站搜索。修正及验收证据见 `docs/acceptance.md`，回归约束在 `test/discovery_test.dart`。

既有网页入口的 `page=2`、`offset` 等尝试返回相同首批；App 某些请求虽 HTTP 200 却为空。上述结果不能算成功分页。

2026-10-26 新证据：官网新 JSON /api/search/result 的 page=2 已取得真实不同结果，程序“网游之”连续页为 10 / 9 条（去重后）。这不是旧 HTML 入口的参数重试，允许使用该分页；仍禁止默认全分类扫描和用旧结果伪装新搜索。

## 强制约束与替代方案

- 禁止将全分类索引扫描作为默认搜索的前置步骤或隐式后台操作。
- 禁止为填满搜索页而把分类扫描结果冒充来源搜索后页。
- 禁止把 HTTP 200、空正文、重复页或仅出现域名 / TLS 元数据报告成“接口已打通”。
- 禁止首批结果等待整页统计详情；应先显示，随后异步补充。
- 默认直接展示可用来源的首批及明确的范围说明；分类补充须用户明确触发。
- 真正分页以服务端实际返回的游标和不同剧集 ID 为证；无法取得后页时必须保留限制说明。

除非用户明确重新讨论并批准，不得恢复上述被否定方案。
