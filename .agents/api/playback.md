# 内置播放与拼接衔接

更新：2026-10-19，工具名称“红葡萄”，应用包标识保留升级兼容。来源协议没有因工具更名而改变。

## 播放链路

1. 卡片提供的是剧集 ID，不把列表预览 `vid` 当完整分集。
2. `HongguoClient.fetchDrama` 重新读取完整分集，再对当前分集调用批量 video model / fallback_api，见 [App 核心 API](app-core.md)。
3. 只列出实际返回且支持的画质。内置 libmpv 通过 FFmpeg demuxer 的 `decryption_key` 选项读取该分集的 CENC 媒体；Referer 随媒体请求传递。
4. 每次切集先停止旧 demuxer，再设置该集的授权材料；无加密媒体清空旧选项。不能把某一集的密钥持久化为全局常量。
5. 清晰度切换重新取得当前集的可用资源并恢复位置；播放失败允许重试取新地址。界面只显示脱敏错误，不直接输出 URL、Cookie、签名或密钥。

Windows 原生播放器已实测两集 1080P、实际画面出帧和拖动。SDK/库存在或 APK 构建成功不等于 Android 设备已出帧。

## 状态与资源

- `PlaybackController` 的来源客户端、切集状态和播放器独立于 `StudioController` 的拼接任务。旧取流响应不能覆盖后来选择的分集。
- 播放自动连播可关闭；拼接选择集合不因自动切集而改变。分集选择每屏最多显示 50 集，可选范围或全部。
- 播放解码线程预算 2、内存 demuxer 缓冲有界，关闭磁盘流缓存。不是固定 CPU 百分比限制。
- 退出播放页释放播放器；Android 切到后台暂停播放。已开始的导出由原有任务流程与前台服务管理，不因播放器释放而取消。

## 拼接入口

列表“拼接”进入工作台。播放页“拼接所选”把完整剧集 ID、所选集号和清晰度交给原任务控制器；控制器重新确认完整分集和画质，再启动下载、缓存复用、拼接与校验。

仅允许一个活动拼接任务。任务进行中仍可看其他剧集；新拼接按钮禁用，不覆盖当前任务。播放页“任务管理”展示同一任务的进度、取消和历史导出，不复制一套独立任务状态。

`lib/playback_controller.dart`、`playback_view.dart`、`services/playback_engine.dart`；验证入口 `--playback-acceptance`。播放器包装层与 native 库的许可证区分见 `THIRD_PARTY_NOTICES.md`。原始播放地址、授权材料和验证截图只保留在 `.local`，不进入源码包。
